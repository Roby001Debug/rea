# MN-Tech 工程适配 · REA

这是从本机 REA 工程适配整理出的可迁移版本，适用于需要分析 EXE/DLL、.NET 程序集、已发布软件包或编译后通讯实现的工程任务。

**快速入口：[中文安装与回退说明](INSTALL.zh-CN.md)。** 安装器默认只预览；加 `-Apply` 才复制技能文件。它不安装 REA 运行时，不修改 MCP 配置，也不覆盖已有同名技能。

## 与上游的关系

- `main` 保留上游 REA 原版；本适配在 `mn-tech/engineering-adaptation` 分支的 `mn-tech/` 目录维护。
- 本分支只新增该目录。上游的源码、原始技能、构建、许可证和发布流程保持原样。
- 可安装技能基于 **rea-agents 6.3.0** 的实际发布内容和 MN-Tech R01 本地适配，现整理为 **R02 portable**。
- 分支所基于的上游主线已经是 6.5.0；这不表示此技能已完成 6.5.0 适配验收。不要把主线版本和技能基线混为一谈。
- 不属于上游官方发布或背书，保留上游 MIT 许可证与署名。参见[来源和差异](PROVENANCE.md)。

## 工程适配包括什么

1. 明确自动选择 REA 的范围；普通日志、连通性、配置比较和完整源码分析按常规工具处理。
2. 优先使用当前会话实际可用的 REA MCP，区分技能发现、配置登记、MCP 连接和可选分析引擎。
3. 遵守各项目自己的规则、既有授权、输出目录、协作边界与停止/恢复条件。
4. 从目标身份、版本与 SHA 开始，区分静态代码路径、离线验证、原厂工具验证和运行证据。
5. 保留原件与失败记录，按范围复用证据，禁止把项目资料和凭据带入公共仓库。
6. 提供 Codex 的自动调用元数据，并保留五份上游分析参考。

## 后续维护

更新上游时，先在 `main` 同步上游，再把新的基线合并到适配分支。不要修改上游技能来容纳本地差异；在本目录评审、更新来源版本和哈希、执行合成检查，再在另一个新会话验证技能发现及实际 MCP 能力。上游 `rea setup` 可能安装其自带技能，升级前先备份已有适配。

其他系统可以人工复制同一技能目录，但本发布没有验证 macOS/Linux 安装流程。只有 Windows 文件安装检查已执行；运行时及分析引擎的可用性需要在目标电脑确认。
